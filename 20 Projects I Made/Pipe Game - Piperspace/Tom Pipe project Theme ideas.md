# Design considerations

It’s not Factorio

It’s an exploration game but you are always building

Players build their own infrastructure

# Where is here?

The megacity. I think it's better if we don't say exactly what this place is. Environmental storytelling should say:

- The structure is old

- Large machines built it and dont care about you, the player.

- You are in the middle of this place, not at the edge.

# What is the player character doing here?

Exploring. If there is a goal, then it should be to find information. You do that by reconfiguring the environment and “stabilising” it so that you may pass to the next area.

If we need some big goal, then the starting area could include a very large machine that needs components. “Rod of Seven Parts” works surprisingly well. Things humans automatically want:

- Open the big door

- Fill in all the empty slots

- Set all the parts in motion

- Collect all the things

- Set things right

# General strategies for naming

Things in the same category should not start with the same letter.

Genetic, hacking, and material sciences influences are key.

# Material naming

# Recipes

**Slates** are the items that set recipes in machines. Each slate sets a different recipe in each machine.

- Cyberstrand

- Nanosplice

- Genobyte

- Chromascript

**Patterns** are inventory versions of machines. A pattern is **projected** onto a suitable area of wall, and the city extrudes it.

# Machines

Machine names are mundane, but their effect and process are not. The output could be one of the original material names, but with a prefix.

- Mill -\> Rendered/Abraded

- Loom -\> Crystalized/Interlaced

- Anvil -\> Tensile

- Press -\> Dense

- Lathe -\> Optimised

- Bender -\> Warped

- Caster -\> Formatted

- Engraver -\> Etched

This gives us 36 intermediate recipes to work with. 28 of which can be 2 part combinations of raw materials. Leaving 10 for higher tier mixes. Assuming we only have 2 inputs to 1 output combinations.

Endpoint (see below) recipes are not included in this, since they are always going to be fixed.

# Important objects

There are a number of static objects of importance found throughout the city.

**Malform Endpoint (Endpoint)** are static machines that produce an end product or increment a global counter when fed their inputs. They should be huge, room encompassing objects that dominate a sector. These could produce machines, slates, or endgame items.

**Synapse Shardblocks** **(Shard)** are used to provide upgrades to the player when their liquid inputs are fulfilled, and their material inputs are provided.

**Stabilisation Matrices (Matrix)** are what provide a sector with Machine cap.

**Access Terminal (Terminal)** Allow the player to change sector door configurations, view the map, and see other sector based information.

**Soma Nexus (Nexus)** A pod which respawns the player. Players can interact with Nexi to change where they respawn.

# Recipes

Sector setup requires 2 resources at a minimum. These resources should not be used for other machines. The player can make these in efficient or inefficient ways.

Each sector has a static machine that makes the 2 resources at a 1-1 ratio.

More efficient machines can be found that are also movable.

Tier 1: A + D = S + V

Tier 2: 2A + 2D = 3S + 3V

Tier 2: A + E = 4S

Tier 2: D + E = 4V

Tier 3: A + D + E = 3S + 3V
